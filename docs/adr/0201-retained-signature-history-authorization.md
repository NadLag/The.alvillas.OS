# 0201 — Retained signature history authorization

F-DOC-06. All 355 approved features remain required.

Provide authenticated discovery for the exact archived document version and paginated native signature events. Reuse document cursors, tenant repositories, the original signature definition, identity-bound recipient encryption, field presentation, current/held authorization and private audit. Expose reference IDs, retained contact values, original document identity and native states; never expose provider credentials, signing links, raw evidence, command nonces or another actor's recovery capability.

Historical reads use current permissions for the actual original source, template origins, financial privacy, signature requester assignment and counterparties. The requester's former permissions do not grant access to another reader. A deactivated requester does not erase historical facts or prevent an independently authorized operator from reading them. A missing current or held permission still denies; late revocation discards both response and read audit. Archived counterparties remain readable with their actual current authority. New drafts and provider effects retain their existing archival and unchanged-source restrictions.

Contact or provider configuration changes cannot replace original encrypted contacts or make retained history depend on an enabled provider. Present the retained contacts against their actual current resource and field policy. Preserve the original instance/version, previous draft and verified sent events across business amendments. Discovery and history issue no provider calls and cannot admit or send a request. Opening a retained draft only selects its original native reference; any subsequent preparation or distribution requires its separately reviewed and authorized command.

Cursor filters bind organization, current reader, original document version or signature, and operation. Bound discovery to30 candidates and event reads to50 events per page. Apply tenant-qualified chronological event anchors. Reauthorize private results after their actual audit. All existing financial rows, applied migration bytes and signature history remain unchanged; no schema migration is required.

Provider webhook persistence, subsequent lifecycle transitions, signed PDF/certificate return and authenticated hosted/provider acceptance remain separate required work. This decision does not mark F-DOC-06 DONE.
