# ADR 0133 — Typed original percentage earnings and history

Percentage runs retain every posting in each selected original journal. Typed witnesses distinguish selected earning bases from the other original postings needed to authorize the complete journal. Each witness has tenant-bound references to the original posting, effective contract, rate configuration, earning policy and resolved property, reservation, task, owner and geography. The configured run unit groups selected postings for one person and assignment; the existing exact Money calculation rounds that earning once.

Retain the original journal total for the posting's currency as an immutable source value. SQL independently compares it with the original debit postings. Authorization uses each original journal and the combined exposure across distinct journals, alongside original salary rates, whole beneficiary earnings and the whole run. The total is calculated from retained postings and supports bounded history reads without repeatedly loading complete journal graphs. Audit masking requires the same original financial and salary access as business reads.

The original run, lines, witnesses, creation audit and outbox receipt must retain their matching actual row transaction identifiers. PostgreSQL savepoints can assign a subtransaction identifier while `pg_current_xact_id()` returns the outer transaction identifier. Admission therefore retains final row-to-row comparisons, immutable receipt boundaries and unique complete witness slots. This supports real savepoints while denying later source appends. See [PostgreSQL subtransactions](https://www.postgresql.org/docs/16/subxacts.html) and [transaction identifier functions](https://www.postgresql.org/docs/16/functions-info.html).

Migration 113 preserves all prior applied SQL bytes and all existing validation branches. Its rollback qualification invokes the actual writer under a NOBYPASS role, exercises 23 source, history, authorization and integrity checks, and retains 1,000 original posting references across 500 actual property income sources. Exact original earnings are MAD 2.28; replay creates no financial movements or claims. The populated local forward upgrade preserves every prior business value, row version and migration record.

Forward migration 114 admits percentage costs through the existing submission, approval, recognition and settlement system. Source identity is the actual beneficiary and selected original posting, so another assignment or overlapping run cannot claim that earning twice. Both application and SQL take the same sorted source locks and original journal reversal locks. SQL checks the immutable earning and typed posting set against the retained policy. Withdrawal or rejection retains history and releases an unrecognized proposal. Approved history is never repriced from later rules. Rollback qualification exercises the real approval, recognition, partial payout and opposite payment movement under a NOBYPASS role, plus self-consistent forged sources; existing row values, row transaction identifiers and function definitions remain unchanged after rollback.
