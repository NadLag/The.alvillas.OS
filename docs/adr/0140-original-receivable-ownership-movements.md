# Receivable ownership comes from original movements

F-FIN-25 reads explicitly configured debit-normal ownership claim accounts from the original posted ledger. The effective-dated `finance.receivables` rule selects account codes; no default account selection, debtor, payment term, due date or tax treatment is inferred. OTA clearing and bank accounts represent money location and cannot enter these ownership totals. The original reservation's current guest does not establish the historical debtor.

The aggregate includes opening movements before the selected civil-date range, movements within the range and every original opposing movement. Archived accounts retain their history. Credits can produce a negative position; the reader does not clamp it, create a new liability or update a balance. SQL numeric aggregation and `Money` retain exact cents. Counts remain decimal strings beyond JavaScript's safe integer range. Empty configured accounts remain visible at zero. Missing or misclassified accounts reject the entire configuration.

This complete organization aggregate requires independently granted, unconditional organization authority for receivables, financial transactions and salary data. Guest-funded payroll claims can otherwise disclose salary amounts through aggregates. Both the original caller restrictions and fresh stored authority are checked before reading, after reading and after writing the private read audit. Source-scoped views will authorize actual original sources separately. A role name or operational property access grants no financial access. The existing private session/origin/size HTTP boundary and `present` field policies are reused.

The source reader adds no business table or migration and never changes existing financial rows. Seven real PostgreSQL source tests cover explicit configuration, exact large amounts, date boundaries, opposing movements, ownership versus location, currencies, archived history and forced tenant isolation. The protected API and complete receivable assignment, collection, correction and acceptance flows remain part of F-FIN-25; this decision does not mark the feature done. Legal, tax and debtor-treatment decisions remain behind explicit configuration and later attributed source bindings.
