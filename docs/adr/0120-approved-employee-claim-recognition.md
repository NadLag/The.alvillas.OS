# ADR 0120: Recognize approved employee costs as retained beneficiary claims

Status: Accepted for integration; complete F-FIN-24 and staging acceptance remain outstanding.

A cost proposal becomes earned ledger ownership through an explicit recognition command for one actual beneficiary claim. Recognition validates the complete immutable submission, original run lines, performers, completion events, classifications and frozen allocations before selecting that person's costs. It does not resolve replacement contract, allocation or approval rules. The shared submitted-allocation reader retains the supplier recognition checks and exact owner rounding. Individual values retain their storage bounds; the existing aggregate-money schema permits the complete portfolio total.

Each source cost produces a balanced journal using the existing employee payable recipe and batch financial writer. The journal debits the original owner, company and guest allocations and credits the actual employee liability. Recognition moves no physical money and creates no editable balance. Claim, run, original cost, completion, person, property and reservation dimensions retain their actual sources. The original review note describes the cost; private whole-run purposes are not projected into owner statements. Owner statements derive the note through the actual immutable source link, including for an earlier retained journal.

An immutable recognition header covers all and only the selected beneficiary's costs. Unique cost and journal relations, tenant-qualified foreign keys, birth-transaction admission, deferred source and posting checks, complete attributed audits and append-only guards prevent partial recognition, substituted beneficiaries, omitted allocations and duplicate ownership. A recognized proposal cannot release its work through withdrawal. Financial corrections and release after a correction require their own attributed lifecycle; an old source is never edited or deleted to support a retry.

Previously approved earnings remain attributable after genuine staff offboarding. The archived person remains the original beneficiary; this grants no account, role or session authority. Acting accounts still need current independent compensation, salary, expense and financial posting permissions. No statutory payroll, tax, gross/net or accounting-date convention is inferred from an archived identity or a completed operation.

Admission persists the original intent and authorization cap through the existing outbox and financial Inngest consumer. Transport carries only the tenant and durable event reference. Execution reloads the actual request, intersects its retained restrictions with current stored authority and appends an immutable outcome. Exact admission retry, acknowledgement recovery, execution redelivery and terminal failure preserve the same source and result. Another command key cannot recognize an already recognized claim. A closed source posts only through the existing authorized current-period adjustment, retaining the original source instant, actual closed period and decision, current posting instant and reasoned audits.

The final authorization fence reloads the source and checks the complete run amount, every original salary source and independent financial source authority at the database clock. Claim audits require those same actual sources. Linked journal adjustment audits additionally require the original compensation and salary authority. Audit listing and export apply both caller restrictions and freshly loaded stored authority before disclosure; audit JSON cannot grant access. Owner statement access continues to disclose the actual owner's slice independently of salary access.

Calendar instants come from the installed current IANA data and must agree with PostgreSQL before any recognition write. An outdated runtime or a disagreement fails closed. Reusing a validated instant within one authorization pass avoids repeating the same property-date conversion for every cost; it caches no grant, allocation or policy decision. The 500-property path remains asynchronous through the existing worker and its unchanged deadline.

Withdrawal of an unrecognized pending proposal resolves only an existing approval receipt tied to its actual appended withdrawal. Cancellation cannot fabricate a receipt, rebind its source, replace an existing approval decision or rewrite a retained cancellation. The existing notification center has English, French and Arabic withdrawal labels.

All database changes are forward migrations. Existing SQL bytes and financial rows remain intact. New migration files have explicit LF attributes so a later Windows checkout does not change their admitted bytes. Dynamic tenant policies retain their semantics through explicit declarations accepted by the existing static tenant-safety gate. Payments, wallet offsets, other earning modes, corrections, the recognition workspace and authenticated staging remain required feature work.
