# ADR 0229 — Native property team during onboarding

The locked specification's fifth onboarding step assigns people and role assignments. Reuse the existing Person, Role and RoleAssignment records and Team writer. The wizard must not introduce another team, account, role or compensation model.

Reviewing a new assignment requires an explicit existing person, role, nullable account, effective interval and assigned-to-me condition. Native admission supplies the actual predecessor Property as the only scope and the command's single canonical Team audit reason. An explicit null account must not select a person's account automatically. Dates normalize to exact ISO instants through the existing Team field and interval validators.

An approved organization rule must enable LINK and/or ASSIGN and state the minimum assignment count. No default minimum or implicit staff assignment is selected. Empty existing-team capture is admissible only when the actual approved rule permits it; ASSIGN must contain a real new assignment. The bounded batch ceiling limits the protocol, while business readiness remains configured and is also subject to the later whole-configuration review.

Read and admission require independent held and stored Onboarding, Owner, Property, Team and role authority. New assignment also requires the canonical delegation checks for the actual Property and every actual role permission; a role name alone grants nothing. Pin role permissions, account/person state, assignment intervals, parent and policy, and recheck after audit. Role or delegation changes cannot loan access to an earlier held context.

Compensation remains attached to the canonical role assignment and protected by its own financial permissions. This producer must not infer compensation, create financial movements, payout access or credentials, or activate a Property. Complete original assignment history belongs in the existing purpose-bound private envelope, with creator-owned nonce recovery and append-only native audit/outbox admission.

The contracts alone do not enable TEAM in the shared routes. Native source readers, canonical transactional assignment, immutable history and additive database guards, private APIs, localized UI and full acceptance remain required. Existing 225 applied migrations stay immutable; a later migration must extend the closed native shape only after the Agreement dependency.

Migration 226 extends the closed shape with LINK/ASSIGN and adds a Team-only native guard. It retains the original migration 225 guard function and every earlier step's behavior. The new guard validates the actual consecutive Management/Team predecessor, approved organization modes/minimum, exact Owner/Property source, current Person/Account/Role/assignment version graph and permission witnesses. ASSIGN also requires each canonical assignment and its attributed audit in the same transaction. Native audit/outbox birth constraints and existing append-only, tenant and financial guards remain in force. No new business table is introduced. The applied SQL is immutable; later corrections require a later migration.

Original Team history checks independent current and held source access using metadata before decrypting its purpose-bound envelope. Actual recorded membership may prove the original Person/Property relationship after archival. History does not load current replacement names, conditions, account values or role permissions, and original account/Person/role identities cannot be substituted. Creator-owned nonce recovery does not transfer to an authorized colleague. Operational review and Team history do not decrypt the financial Management predecessor; its original independent financial read checks remain effective.

The shared TEAM dispatch now calls the guarded226 producer for review, durable admission, original reads and creator-owned recovery. Team options use authorized predecessor metadata and their own current/held Owner, Property and Team checks; an explicit operational entry never fetches or decrypts the Management financial record. Candidate selectors scan at most50 identities, authorize metadata, and request private labels for at most20 permitted rows. Existing canonical delegation supplies role availability; it is not replaced by a parallel permission engine. EN/FR/AR forms require explicit Account/null, actual UTC dates and a reviewed reason. Native and browser acceptance, populated restore and exact-head release gates remain separate.

Identical concurrent nonces exposed a source-capture race in the rate-budget preflight before the admission transaction acquired its command lock. Both transactions now acquire the same existing per-organization/nonce advisory lock before reading that nonce and its sources. This serializes identical requests through source capture or original recovery, while different commands still face predecessor/source conflict checks. It does not cache authority, remove late fences, change financial history or relax transaction/test budgets. The original failed race and successful affected16-case verification are retained.
