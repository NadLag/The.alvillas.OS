# Employee compensation claim corrections

An approved employee claim can contain several immutable cost journals. Correcting its earned amount must preserve the original contracts, work or financial sources, approval, recognition, payments and audits. The supplier claim reversal flow already establishes the financial behavior: reverse actual payments first, then append the exact opposite of every original recognized cost in the current open period.

An employee correction therefore names the original submission, beneficiary claim and recognition. Its input accepts an idempotency key and reason. Amounts, beneficiary, allocation, accounts, currency and posting date come from the original records and the database clock. The correction header and each typed line are append-only tenant records. Composite foreign keys bind each original cost and recognition line to exactly one original journal and one opposite journal.

The existing settlement preparation supplies the original source validation, run and submission locks, actual payment receipts, and held plus fresh authorization. Correction also checks financial creation at the actual opposite date. Active payments and wallet offsets block correction. The original liability must equal the original approved amount before correction and become zero through actual movements afterwards. No stored balance or old financial row is edited.

Database admission requires co-birth of the typed correction and its opposite journals, every original beneficiary cost, unchanged original approval, an open current posting period, no active settlement, zero derived liability, and the exact attributed correction audit. Existing generic reversal guards still enforce the complete opposite posting multiset. Recognition postings accept an opposite only through this typed correction. New cost admission releases the corrected claim's original earning identities only after the guarded correction exists; replacement earnings use the ordinary new run, proposal and approval flow.

Claim and journal audit resources retain the original salary and complete financial source requirements together with the actual opposite journal dates. Historical recognition and payment readers use these additional sources. A smaller correction cannot expose a larger original income base or bypass salary restrictions.

The forward migration is qualified with the actual application and a restored 500-property financial portfolio under rollback before local admission. Applied predecessor SQL and original row values and row versions remain unchanged. This decision implements the financial correction engine; authenticated durable correction commands and their native workspace are subsequent integration work within F-FIN-24, which remains in progress until complete acceptance, including staging.
