# F-NTF-02 — Durable personal notifications

Notification delivery is local and transactional: a business mutation writes the existing outbox and its recipient's notification in the same tenant transaction, acknowledging the local event as dispatched. The dispatcher also registers an idempotent consumer, so replay is safe without waiting for external email or job providers. A unique organization/recipient/event key prevents duplicates. Language preference changes notify the account itself; generated task assignments notify the assigned account. This does not introduce channel preferences or a general event routing engine.

An authenticated account has a narrowly scoped capability to view and mark its own inbox, following the existing own-security capability pattern. No role grants access to another inbox. Generic localized event messages contain no record titles, personal information or money. Unavailable records retain their historical notification with no destination; every open rechecks the current record, assignment and authorization. The DTO uses `present` and excludes recipient/target identifiers. Lists use indexed keyset pagination and an exact recipient unread count in a repeatable-read snapshot; target authorization is batched per page. First-read timestamps and notification history are protected by a database trigger. Read mutations use the existing audit writer.

The migration only adds notification storage and a supporting account composite key; it does not rewrite business or financial history. Production migration and promotion remain manual owner decisions.
