# Bounded input for complete native owner reports

Native owner reports can contain more text than the ordinary document interpolation limit. Their six sections retain the existing exact declarations, at most 200 bindings and 20,000 UTF-16 units per binding. A server-selected input profile admits up to 16 MiB of rendered JSON, sufficient for those bindings in UTF-8 plus escaping and metadata. Template definitions retain their original size limit; generated PDFs retain the actual configured archive limit and the renderer's existing maximum.

Only the authorized native `ONBOARDING` resolver selects this profile. Both financial and sensitive classification remain mandatory. Public generation commands cannot supply a profile or values. The immutable generation identity, encrypted input and encryption purpose authenticate the selected profile; original unprofiled identities and encryption contexts remain unchanged.

An additive migration retains every original native generation guard. Its larger bound requires the explicit profile and an actual tenant-bound native Review reference. Other source kinds and all unprofiled instances retain the original input limit. No document, admission, migration history, financial row or balance is rewritten. Package orchestration still requires actual archived English and French versions; input acceptance cannot count as package completion.
