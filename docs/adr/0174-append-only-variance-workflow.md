# ADR0174 — Append-only variance workflow

Keep original financial variance facts, bank associations, staff assessments and physical observations immutable. Assignment, reasoned resolution and reopening append attributed workflow events. Every command binds the reviewed native source fingerprint and workflow version; stale intent fails rather than silently rebasing. Actor/nonce recovery returns its original result only under current source authority. Assignment never grants financial access.

Native source adapters supply current authorized facts. A later staff assessment or source correction invalidates an earlier resolution's fingerprint, reopening a still-different source while retaining its earlier history and assignee. Genuine native matching and unavailable/corrected sources remain distinct from a human resolution. Aging is derived from trusted source/clock timestamps without introducing a deadline, threshold or accounting rule.

Commit the handbook's VarianceResolved and VarianceOpened events through the existing transactional outbox for explicit resolution and reopening. Payloads contain only the immutable workflow event ID; amounts, explanations and recipient authority are not copied into the queue. Exact command replay creates no second event.

Reuse held/current authorization, original provider locks, exact reconciliation measures, tenant repositories, audit writer and nonce-only private command hooks. Store no editable money or derived balance in workflow commands or events. Add native tenant/source/actor constraints, immutable event history and atomic audit without rewriting original rows. Unsupported source adapters fail closed until their native dependencies exist. Laundry's versioned price/expected/actual sources remain dependent on F-LND-04/05/06; the owner-payout source remains on the protected draft payout stack. These dependencies and authenticated staging continue to block complete F-FIN-32/F-FIN-33 acceptance; no DONE status is implied.
