# F-NTF-04 — Persist approval events and route channels independently

The routing implementation in ADR 0034 is retained. There was no saved approval lifecycle to produce approval events. Property operational requests now persist their subject, immutable routing configuration and eligible approvers in one tenant transaction with audit and notification outbox records. This introduces no financial posting, expense threshold, payment authority or change to the financial approval policy evaluator. Financial multi-step approvals remain governed by their existing feature requirements.

Configured people and roles must have current scoped property view and approve/reject permission; selected roles cannot borrow another role’s wider scope during selection. Empty selection fails closed. Recipients are snapshotted independently of optional notification preferences. An authorized selected approver records one terminal decision. Concurrent/repeated requests and identical decisions are idempotent; conflicting decisions fail. Original notification read timestamps survive resolution, and the resolution is immutable.

External channels enqueue one outbox job per source event, recipient and channel. They reuse NotificationChannel and the existing outbox retry machinery. Delivery rechecks active identity, enrollment, access, consent and pending approval state. Email uses the existing Resend adapter, localized catalogs and a stable provider idempotency key. Provider errors are redacted. Push routing accepts an injected NotificationChannel; no production push adapter/subscription lifecycle exists, so selected push work fails explicitly and remains retryable/failed rather than claiming delivery. F-NTF-04 and F-NTF-05 stay IN-PROGRESS until real-provider acceptance. No fake provider runs on production paths.
