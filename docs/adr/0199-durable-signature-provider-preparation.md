# 0199 — Durable signature provider preparation

F-DOC-06. Scope unchanged: all355 approved features remain required.

Extend the existing native signature draft with a reviewed preparation intent, a durable external attempt and encrypted provider evidence. Reuse the platform's tenant transaction, current/held authorization, native document download, field presenter, configuration engine, audit writer and reference-only outbox. As with external payment evidence, record an independently verified provider receipt as an append-only system fact tied to its original authorized attempt; access to its private contents continues to require actual source and counterparty authority. No financial admission or movement follows from signature evidence.

An intent captures its original actor, nonce, canonical request, layout, exact archived PDF, native recipient identities, legal configuration references, selected account scope and configuration version. Retain the original configuration JSON alongside its validated normalized value so normalization cannot replace the authoritative config_rule record. No business expiry, reminder or notification default is supplied by code. Sending stays disabled without the owner-provided account and legal/certificate configuration. A configuration reference is not a claim of legal approval or an authenticated provider acceptance.

Before exporting a company PDF, read the configured account's existing scope envelope and verify its actual team and reference. The origin comes from the configured provider credential endpoint and must match the selected policy. An immutable scope ownership row uses a global primary key and tenant-qualified references: forced RLS must not hide a conflicting organization and allow a second claim of the same external account scope. An immutable attempt commits before the single external creation POST; native uniqueness permits at most one preparation effect for a signature. Competing authorized intents remain visible and cannot replace the chosen attempt. Another command or delivery retry cannot reset an uncertain effect. Recovery can reconcile a known external envelope after validating its reference, original PDF bytes, account, recipients, signing order, methods, expiry, notification controls and field geometry.

Disable recipient-directed substitution. Preparation creates a private provider draft; a separate explicit command is required for distribution. Documenso may return its unsigned original for a premature signed download, so binary retrieval verifies completion before and after the authenticated, bounded, redirect-free read. A completed-looking response alone cannot create a native SIGNED event. Signed return must retain the original business instance and preserve effective ordering across later amendments.

Provider tokens, raw receipts, private contact data and observations use identity-bound AEAD with explicit historical key support and no authentication-secret fallback. Public responses, canonical audit and outbox contain only references, counts and safe state codes. Provider evidence has no public ingestion endpoint accepting caller-generated outcomes. An authenticated webhook and the original native provider binding are required for later state ingestion. Unconfirmed preparation remains reconcilable; it never justifies another automatic POST or a fabricated sent/signed state.

Migration195 is a forward migration, frozen after its populated local application. The previous178 business table bodies and tuple versions, and all194 earlier migration rows and checksums, remained unchanged. Its four new tenant tables begin empty. Native RLS, immutable source links, atomic audit/outbox and independent attempt/evidence guards apply to the new records. No production migration is included in this acceptance. Provider distribution, persistent webhook transitions, signed PDF/certificate return and hosted acceptance remain required before feature DONE.
