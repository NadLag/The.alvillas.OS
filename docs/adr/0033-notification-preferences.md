# F-NTF-03 — Personal channel preferences and required security delivery

The existing notification repository owns preferences and delivery decisions. Each tenant/account has one optional preference row; its absence enables account and assigned-work in-app updates. Authenticated self-service uses the existing own-inbox capability, active-account checks, tenant transactions and audit writer. The account lock serializes saves so each audit records the committed previous settings. Reads return only the settings through `present`. PostgreSQL enforces tenant/account ownership and required security flags. Preference identity cannot be rewritten or deleted.

Only implemented delivery paths are offered: optional in-app account/work categories, required in-app security alerts, and required invitation/recovery emails. The shared policy rejects unknown events/channels and cannot suppress required security events. Session revocation produces a real, generic security notification through the existing transactional outbox; opening it rechecks self access. Optional switches never grant record access. External provider readiness and actual delivery acceptance remain F-NTF-01 requirements.

Preferences apply when delivery is decided. Delivered history remains available; a terminal dispatched outbox event cannot create a previously suppressed notification when replayed after an opt-in. The additive migration creates preference storage and expands the existing notification kind constraint without rewriting financial or business history. Production migration and promotion remain owner decisions.
