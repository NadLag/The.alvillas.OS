# F-NTF-04/05 — Durable browser push over the existing notification outbox

Routing, recipient selection, preferences, approval snapshots and the notification inbox remain the shared implementation. A push channel job creates tenant-scoped delivery rows for the subscriptions present at first dispatch. Each browser commits its own result; successful browsers are skipped on replay. The existing dispatcher schedules retries using the effective `notification.push.delivery_policy` rule, exponential delay and bounded provider Retry-After. Permanent failures and exhausted attempts remain visible. HTTP 404/410 revokes the affected subscription; VAPID rotation requires subscription renewal. No provider acknowledgement is reported as confirmed browser display.

`web-push` owns RFC8291 encryption and VAPID signing. Keys stay in server environment variables; subscription endpoint/key material uses the existing versioned encryption helper. Browser-vendor endpoint validation prevents arbitrary server fetches. Tenant/account/session composite foreign keys, forced RLS, immutable ownership and non-deletable delivery history protect persistence. Subscriptions are tied to an active sign-in, reconciled on permission changes/focus/online, and revoked on logout or through the settings page. Shared browsers must explicitly enable a new sign-in. Old endpoint ownership is never transferred between accounts.

Every device attempt rechecks current recipient access, enrollment, consent, session validity and the record's state. Mandatory in-app session-security and account-access email policy remains server-owned. Push carries only a delivery identifier. The service worker resolves its localized message through the current authenticated session before display; clicking resolves authorization again and records the first open/read timestamps. The worker does not cache authenticated pages or business data. Delivery history distinguishes pending, provider acceptance, browser display, open, suppression, invalid subscription and terminal failure without exposing addresses or subscription secrets.

Push services do not promise exactly-once network delivery. A process crash after provider acceptance but before the database commit can cause a retry. Stable per-device provider topics and browser notification tags collapse that uncertain retry; durable acknowledgement prevents resending after a committed success. Desktop/mobile tests use a test-only vendor transport and CDP push event injection while running the actual service worker, authorization, application actions and PostgreSQL. Real-provider staging acceptance is recorded separately and remains required for DONE.
