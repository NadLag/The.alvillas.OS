# ADR 0225 — Native Operating Profile during onboarding

The Operating Profile step uses the existing Core property operating profile. LINK records an unchanged actual configuration; UPDATE submits every operational choice to the canonical Core update service. Neither mode creates another property or agreement model.

Updates cannot select services through implicit Core defaults. Existing Core cadence and configured mid-stay rule validation remain authoritative. Native source admission must bind the actual Owner, Property, predecessor, profile tuple and any approved referenced rule versions under current and held authorization. Both modes retain original before/after values in immutable private history. Read projections preserve original nullable fields, notes and service labels without applying update-time trimming or limits to captured history.

The producer must extend the closed SQL shape and corresponding source/audit/outbox/birth guards together. Existing shared APIs remain closed for this step until native admission and recovery qualify; client flags cannot complete or activate onboarding. All224 applied migration files are immutable. The additive Operating Profile guard retains the original Owner/Property shapes, audit/outbox birth constraints and unsupported-activation rejection; UPDATE requires its actual same-transaction canonical Core update and audit.

Private review and history projections show the actual referenced rule version, threshold and task template. Complete original rule metadata remains in the existing authenticated encrypted payload; later Core or configuration changes do not replace recorded values. Receipt-only recovery requires current operational source access without expanding into private export access.

Current private form options use the same session, source and held/current authorization helpers. They require personal export, bind the native predecessor and Property, and re-read the profile, policy and actual referenced rule after audit. The client retains private form state only in memory; durable browser storage contains the existing command nonce only. Core cadence choices and localized field labels are reused.

Plaintext native rule witnesses contain only the actual candidate scopes and resolved rule version/tuple pins. Complete original registered values and metadata remain in the existing authenticated encrypted payload. Additive224 closes this source shape without rewriting earlier history or changing original encryption purposes and command recovery.
