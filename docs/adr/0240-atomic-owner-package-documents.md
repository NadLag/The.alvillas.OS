# Atomic native owner package documents

An owner package admits every configured original language document together. English and French are mandatory; an explicitly configured Arabic original requires its own approved wording and renderer. The package stores an immutable, tenant-bound identity plan that references real canonical document instances. The original command, policy, source and captured authority use purpose-bound encryption.

The package admission calls the existing document application service in the same database transaction. Both document instances, their canonical worker outboxes, the package, its language items and audit evidence commit together. Template and native source reads require current and held authority throughout. PDF rendering and storage occur after commit through the existing document workers; there is no second document model, provider implementation or retry policy.

Package state is derived from actual canonical generation receipts. A request, an accepted child or one completed PDF cannot count as completion. Every configured language must have its distinct immutable archived version. If a pending child's source changes, the partial original remains recoverable and the package cannot claim completion. Completed originals retain their historical bytes and current archive access rules.

Package recovery requires the original creator, current and held onboarding scope, and each actual document's independent archive authority before decrypting the private package command. Final activation, delivery and go-live readiness consume these facts through their own approved requirements. They cannot infer an operational transition or delivery from document admission.
