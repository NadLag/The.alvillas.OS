# F-NTF-07: scheduled notification digests

Digest choices belong to the existing tenant/account notification preference. Enabling a digest consents to operational email; disabling that channel pauses it. Changes invalidate queued batches through a revision. Schedules use IANA local calendar time, including gaps/folds and quiet intervals; overdue schedules coalesce into one current batch, without catch-up email bursts. Delivery limits, retry policy and initial schedule choices resolve through `config_rule`.

The existing signed Inngest minute dispatcher schedules batches and consumes their transactional outbox events. Account locks serialize scheduling, preference changes and sending. Each unread operational inbox row can belong to one digest delivery; the composite tenant/account foreign key prevents reassignment to another recipient. An empty or unauthorized batch sends nothing. Emails contain localized event labels and authenticated inbox links, with no record titles, guest identity, financial values or cross-recipient counts. Every link invokes current inbox ownership and record authorization.

Delivery history reuses `notification_delivery`. The exact request is encrypted and committed before provider contact. Retries recheck current access, unread state, email address and preferences; changed content suppresses that immutable request. The stable Resend key is never retried beyond a configurable window capped at 23 hours, below [Resend's 24-hour retention](https://resend.com/changelog/idempotency-keys). Acknowledged requests are recorded as accepted; a signed Resend receipt with matching tenant, delivery and provider references advances them to delivered. Svix validates the raw body, timestamp and signature; the application key needs sending access for the verified domain. The webhook secret is configured privately alongside that key. Failures and suppression remain visible and audited without recipient addresses or message bodies.
