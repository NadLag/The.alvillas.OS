# ADR 0260 — Native canonical service catalog

Status: accepted for implementation. Owner decisions, provider activation and restricted hosted acceptance retain their existing gates.

`services.pricing` is the sole service catalog. Onboarding, configuration and catalog authoring use the same registered schema object, existing scope/version resolver and configuration writer. Existing optional fields and unknown extensions survive an individual item edit. A publication appends a property configuration version; it never edits an original or creates a second price table. More specific agreement/channel definitions must use their existing configuration workflow rather than being shadowed by an ineffective property write.

Fulfillment terms explicitly reference immutable native allocation and tax versions, configured internal cost, actual supplier/person identities, an approval reference and the existing bounded condition format. Publishing requires the currently selected financial rule versions. No commission, tax treatment, owner/company proportion, price or provider default is invented. Native registered currency precision must represent the exact configured selling price and cost; validation does not round them. CUSTOM remains a reviewed quote requirement.

Staff reads and commands require independent service, property, configuration and financial source grants from both the held context and current account. Financial policy values and provider labels follow metadata authorization. Provider people use their actual memberships; the catalog property cannot manufacture a person's scope. Batched source reads and bounded keyset pages avoid per-item repository queries. Projections expose registered fields rather than unknown original extensions. Current financial authorization also protects retained configuration audit content and reasons.

Publication reviews bind the draft, winning catalog, physical sources, financial policies, currency and authorization fingerprints. The canonical configuration lock and a command lock serialize writes and retries. A successful version, audit and metadata-only outbox receipt share one transaction; the database requires the actual version and audit to be born in that transaction. Receipt identity and payload are immutable while ordinary dispatch state may advance. Reusing a command identity with a different command is rejected. Nonce-only recovery reads the original recorded outcome under current source rights. Archived providers remain readable in authorized history and are rejected for new fulfillment publication.

The EN/FR/AR property workspace loads private values through same-origin, account-bound, no-store requests. Review precedes publication. Only a command nonce may enter session storage; forms and history clear on hidden/offline transitions and denied access. Original configuration versions remain independently readable and paged. This staff catalog does not itself delegate guest ordering, create fulfillment tasks, collect payment or post accounting: those remain the required native F-GST-08/F-SVC-02/F-SVC-03 lifecycle and effects.
