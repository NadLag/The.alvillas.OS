# ADR 0119: Retain emergency employee cost notices by actual owner slice

Status: Accepted for integration; full feature and staging acceptance remain outstanding.

Employee cost proposals use the existing configured emergency approval policy. When that policy bypasses owner approval and requires a notice, submission must retain an actual authorized owner inbox receipt before committing. The existing notification engine delivers the mandatory financial notice; optional notification preferences cannot suppress its required inbox receipt. Email and push continue to follow the existing channel and preference rules.

Each notice envelope binds the actual immutable cost, submission, owner and frozen recipient. Its destination is the durable event ID. The shared inbox resolves its public reference through the stored source envelope. The public notice discloses only that owner's gross share, allocated cost, review note, category, cost date and whether the source proposal was withdrawn. It exposes no whole-run header, employee identity, salary, contract, other-owner allocation or policy dump. Property names additionally require current independent property access. Reading the notice requires an actual receipt for the current account and both caller and current expense authority over that owner's original cost slice. Salary access is independent.

Approval and notices share one employee cost resource projection, retaining the actual financial record, property, owner, original cost calendar and submitter. Notice delivery rechecks actual active recipients and their current grants. Submission repeats these audience checks after deferred source guards; an unavailable receipt or changed audience rolls back the source, receipt, audit and outbox work together. Exact submission and worker retries retain the original source and do not duplicate notices or attributed bypass audits.

Portfolio preparation collects required notice audiences and resolves their current authority together for each validation pass. Delivery loads thin cost projections and uses the existing shared batch notification writer. The final audience check loads fresh authority after the deferred guards; observations are not reused across passes or requests. This keeps the 500-property workload within the existing worker deadline while preserving every source, receipt and authorization check.

Forward migrations retain every previously admitted notification kind. A deferred source check requires every configured owner notice to have an actual inbox receipt and its attributed bypass audit. Additional envelope and receipt guards bind the frozen actual source and recipient, reject source substitution and preserve immutable identity. Financial notice events and receipts cannot be deleted; ordinary read and delivery state can still advance. No applied SQL or historical row is rewritten.

The English, French and Arabic notice page uses the existing private financial read hook. Connection loss, denied access and revalidation clear its private contents. Withdrawal keeps the original notice and source history. Submission, notice delivery and review make no accounting movement. Recognition, settlement, additional earning sources, corrections and authenticated staging remain required F-FIN-24 work.
