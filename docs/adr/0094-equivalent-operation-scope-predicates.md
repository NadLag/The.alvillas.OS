# 0094 — Group equivalent operation permission predicates at property scale

The supplier invoice acceptance data exposed an existing operations query limit. Assignment and swap pages expanded every authorized property into a separate state predicate for both view and assignment. PostgreSQL rejected a retained native request with 51,621 bind variables against its 32,767 parameter limit. The same error is reproducible locally, and a real 4,000-property regression fails on the former query.

Authorization still evaluates each grant, property and task state through `authorize()`. The query builder unions allowed states separately for unrestricted and own-assignment access within each property. An unrestricted state removes only that same state's redundant own-assignment predicate. Properties with identical resulting state/assignment predicates share one `IN` filter. Explicit job grants still load tenant-scoped records and pass their actual resource through `authorize()` before their exact identifiers are grouped.

This preserves the prior permission disjunction without truncating properties, removing state checks or widening an own-assignment condition. It changes neither business rules nor financial data or migrations. Real PostgreSQL tests cover the former parameter overflow and compare grouped query results with direct authorization across property/state/assignment/job combinations. Existing scope-before-pagination and separate view/assignment regressions remain unchanged.

The retained larger roster also exposed a separate 1,000-row limit in configuration property choices. That limit ran before the application filtered authorized scopes and could hide a newly created, authorized property. The repository now returns every active tenant property in deterministic city/name/identifier order; the existing application authorization filter remains responsible for visibility. The same 4,000-property regression proves the scope list is complete and contains the operation's actual property. No property is deleted or removed from acceptance data to make a selector pass.
