# ADR 0152: Configured reminders from original receivable history

Date: 2026-11-02

`finance.receivable_reminders` explicitly selects the original aging source, organization calendar, current configuration author as principal, local send time, stage offsets and optional repeat intervals. There is no fallback schedule, threshold, principal or audience. Stage names support EN, FR and AR. The existing notification-routing editor selects organization recipients and supported channels; assignment and property routing are unavailable for this aggregate financial source.

The existing signed dispatcher polls the schedule. The configuration author must retain active account/security enrollment and unconditional organization authority for receivables, journals and staff compensation, plus receivable configuration authority. A tenant with an unavailable principal or configuration returns a blocked step result without preventing other tenants' dispatcher work. Unexpected failures still propagate through the original background retry mechanism.

Each tick locks the original configuration keys and reuses the canonical complete aging projection and Money validation. The complete-source validator also serves CSV export; reminders introduce no alternative balance calculation. Civil-day stages use the configured company timezone. Unscheduled and settled claims produce no occurrence. Missed ticks catch up to the current configured stage and repeat occurrence. Stable policy/claim/stage/civil-occurrence/recipient keys bind the original outbox source. Per-policy, routing-version, currency and company-day completion audits make repeated ticks bounded; notifications, source validation, completion and final authority/configuration fences commit atomically.

Recipient selection is independent of routing membership. Each recipient needs current, unconditional organization access to all three financial sources and valid security enrollment. Inbox and channel delivery re-evaluate those grants, the original policy and audience versions, the current canonical outstanding claim and its configured occurrence. Settling a claim or revoking authority removes its destination without rewriting the notification history. Preferences and explicitly configured channels remain effective. Existing delivery, outbox, audit and authorization helpers are reused.

Notification envelopes contain source identifiers, currency, civil dates, stage and the frozen routing version. They contain no amount, debtor name or claim purpose. An additive migration retains all existing notification kinds and binds the new envelope and inbox receipt to the actual tenant claim, configuration and source event. Source identity and history remain append-only; the existing first-read timestamp behavior remains valid. No financial row, balance or business table is added or rewritten.

The receivable workspace exposes a localized schedule editor only with independent financial and configuration authority. Saves use the canonical configuration writer and attributed reason, retain original versions, and reject stale or concurrent edits under the existing configuration lock. Current run metadata is read from immutable completion audits. Offline and revoked access clear configuration drafts and financial state from memory. No browser persistence or external provider call participates in the configuration or financial transaction.

Release acceptance requires actual PostgreSQL concurrency, authorization, tenant, source and history checks; native EN/FR/AR desktop/mobile flows; the actual portfolio scale; exact-head mandatory CI; and authenticated staging. Implemented controls do not change feature status or waive blocked staging acceptance.
