# 0091 — Invoice drafts retain immutable source revisions

Supplier invoices use the canonical supplier identity and an independent financial permission. Creation records an immutable request fingerprint and organization reference. The exact supplier invoice number is unique within that supplier; authored casing is retained. Issue dates and optional due dates are source facts. The application does not invent a payment deadline, calculate tax or change the supplier's stated dates.

Each draft edit appends a new revision and new allocation lines, then changes the invoice's current revision with an exact version check. Earlier revisions and lines cannot be updated, deleted or extended after their total is complete. Archive/restore changes the draft's visibility while retaining every source revision and audit event. PostgreSQL checks tenant references, reservation/property consistency, exact amount/currency conservation, source identity, revision ownership, author and same-transaction audit attribution. The current revision foreign key is deferred so the complete cyclic source can be created atomically.

Invoice access requires current and caller organization-level invoice authority and supplier source visibility. Operational property and reservation choices additionally use their own current grants before pagination and presentation. Writes resolve authority again after lock waits and before audit/commit. Draft edits share the tenant invoice lock with the later settlement workflow; supplier edits share the existing canonical supplier lock. The native editor uses paginated source search, supports 500-property allocations and exposes prior revisions without editing them.

Draft authoring creates no financial movement. Recognition, configured approval snapshots and settlement are separate transitions built on ADR 0090 and the existing approval and financial writer. F-FIN-23 remains incomplete until those transitions, their native workflows and all Definition of Done gates pass.
