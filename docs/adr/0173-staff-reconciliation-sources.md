# ADR0173 — Retain original staff settlement reconciliation

Compose F-FIN-32's shared evidence plan when an authorized employee payment, beneficiary wallet offset or complete opposite journal commits. Expected money comes from the actual recognized employee-liability postings. Actual money comes from all native payment/offset liability postings and their original opposites. Verify tenant, beneficiary, claim, original recognition links, sealed journal identity, account type, direction, currency and precision. The signed difference must equal the negative of the outstanding liability independently derived by the existing repository.

Each audit retains a complete historical assessment of those original facts; it does not allocate the claim a second time. A partial settlement keeps the remaining liability visible as an open difference, referencing the original executed settlement action. Exact settlement is matched. A complete reversal retains both original sides and their genuine zero net actual; it creates no synthetic movement or tolerance policy. Existing payment status, cost recognition, wallet custody and source-budget rules remain unchanged.

Write the existing required payment/reversal audit and flush the existing native guards first. PostgreSQL's deferred finalizer then seals the newly created journal. Assess only fully sealed original facts and append a linked `finance.employee_settlement.reconciled` audit, still inside the same tenant transaction and before its final held/current authorization fence. Any reconciliation, audit or final-authority failure rolls back the complete payment, native seal and both audit events. No unsealed journal is accepted as retained reconciliation evidence.

The original strict payment-audit schema, request hashes, responses, idempotency recovery and prior audits retain their exact contracts. Replays return the original receipt without appending another assessment. All applied SQL remains unchanged. No new business table, competing ledger or migration is introduced.
