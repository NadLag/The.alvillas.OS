# Native activation composes the existing owner package and delivery

Activation owner effects use the admitted native request, its actual identifier-only outbox, original creator cap and current configuration. Approval, onboarding/property edit and recorded independent source authority are checked before the original key ring. The request's original command hash, policy and current reviewed source must still match.

The existing immutable activation UUID is the package command nonce. Its distinct immutable native outbox UUID is the email command nonce. These identities survive attempts and process interruption without another nonce registry or mutable retry payload. Recovery verifies creator, session, Review, Owner, Property and canonical child reason before using a matching child. A conflicting command remains a conflict.

Package admission and completion reuse native F-ONB-05 and canonical document workers. Email admission requires both actual archived originals and queues native F-ONB-06; the existing canonical email worker owns provider transport, configured retries, suppression and signed delivery receipts. Actual provider acceptance stays separate from verified delivery.

These internal adapters supply genuine child receipts. They do not append successful activation phases, manufacture Workflows/Tasks/Notification outcomes or change Property status. The dependency-ordered activation producer and all five canonical effect proofs, its additive SQL guards, private multilingual UI and restricted hosted acceptance remain required before native operational activation is enabled.
