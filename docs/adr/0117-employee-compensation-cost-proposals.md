# ADR 0117: Bind employee cost proposals to completed work

Status: Accepted for integration; feature acceptance and staging remain outstanding.

A completed-work run records an earning expectation. A cost submission retains every positive original work amount and classifies it using an explicit cost date, category, cost center and review note. Amounts, currencies, beneficiaries and completion events come from the actual run lines. Zero-valued work remains in the run and does not create a liability. The existing property cost engine resolves agreement allocation, whole-submission review thresholds and configured recipients. No accounting or statutory payroll convention is inferred from the cost date.

The immutable submission groups separate beneficiary claims and immutable source costs. It has no editable amount, balance or payment state. Approval uses the existing approval request, stages, recipients, decisions and notifications, with tenant-qualified employee source relations. Submission and approval make no ledger movement. Recognition, payments, offsets, other earning sources and corrections remain required parts of F-FIN-24.

Complete artifact access requires the actual run total, every beneficiary's salary sources and independent financial source authority, retaining both caller restrictions and current stored grants. Owner review instead projects the owner's actual configured cost slice through the existing expense permission model. It returns that review note and slice, without the full submission header, employee identity, rates, private policies, other owners or hidden stage counts. Audit disclosure binds the actual submission relation and the same salary authority; audit JSON cannot grant access.

Financial source projections also retain the actual run creator during request admission, execution and reads. One shared projection prevents an assigned-record restriction from losing that source fact between phases. A different reviewer with an assigned-record grant still cannot read the creator's proposal. Salary attribution follows the actual performer for self completion, offline sync and proxy validation, including a person without a login.

An active cost reserves its actual completion event across separate draft runs. Withdrawal appends an attributed record, retains the original source and decisions, resolves pending notifications and releases that reservation. A changed earning contract before a new proposal requires a fresh run; historical proposals retain their original terms. Historical reads remain available under current authority after withdrawal or run cancellation.

The 500-property workload exceeds the synchronous request budget. Submission therefore persists an immutable request and original authorization restrictions, then uses the existing outbox and financial Inngest worker. Event transport contains only the tenant and durable event reference. Execution reloads the actual request, retains the original restrictions, checks current authority and commits the submitted source with its immutable outcome. Worker redelivery, exact HTTP retries and terminal failure receipts reuse that result. Public status and paged detail contain no authorization cap, fingerprint, nonce or policy dump.

Forward migrations preserve previously applied SQL. The source adapter extends the shared stage guard and validates the fold of actual decisions and attributed audits. Completeness is checked on the deferred immutable header; child admission additionally binds the actual source, birth transaction and unique beneficiary/completion. Rechecking the entire batch for every child was redundant and made the portfolio case exceed its test budget. The header and admission constraints preserve complete-source protection without that repeated scan. Calendar boundaries are resolved once per distinct timezone within each authorization check, using the canonical calendar helper; no business rule or grant is cached.

Emergency submission fails closed when configured owner notices require the employee source adapter recorded in `docs/STUBS.md`. That adapter, recognition and settlement remain unfinished feature work. No production migration or promotion is authorized by this change.
