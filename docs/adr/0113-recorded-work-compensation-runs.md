# ADR 0113: Retain completed-work compensation runs as immutable source records

Status: Accepted for integration; full feature and staging acceptance remain outstanding.

A compensation run records the contractual expected value of genuine completed work. Each selected job binds its actual performer to one explicitly confirmed role assignment, its effective per-job compensation and configuration, and its unique immutable completion event. Direct completion, offline synchronization and distinct-person proxy validation use the same validators as the protected compensation previews. Existing role-assignment contracts remain the rate source.

The organization explicitly configures the recorded-completion earning calendar, timezone and permitted period length in `staff.compensation_runs`. Application and database calendar bounds must agree. Human selection resolves overlapping contracts. Configuration and contract versions, completion evidence and monetary values remain frozen in each source row. Creation and cancellation have attributed, unique audit receipts and opaque transactional outbox events. Cancellation appends a separate record. Run totals derive from source rows, and financial balances continue to derive from posted journals.

Run permissions evaluate the complete artifact amount. Independent salary permissions evaluate each original rate and the complete beneficiary amount in its actual property, job and earning-date context. Original caller restrictions intersect fresh stored authority after locks and again after source, configuration, audit and deferred-guard checks. The shared source-resource builder also protects audit payloads and reasons using actual persisted run sources. A conditional grant can authorize a concrete run within its monetary limits. The Finance role receives the handbook's salary-view permission; rate editing remains an independent permission.

Migration 81 adds tenant-scoped run, source and cancellation tables, source foreign keys, immutable-history guards and complete source/audit/outbox constraints. Two parent identity indexes support composite tenant foreign keys. The original 80 migrations retain their bytes. Candidate create/read/replay/cancel commands for all completion methods ran under a restricted role in rollback-only rehearsals before the migration was frozen.

Batched source reads reuse the configuration scope/version resolver and the canonical compensation validators. A real 500-property run uses 113 queries, matching a one-job run; measured creation took 825 ms and preserves financial journals and postings. Authenticated source reads return explicit paginated DTOs. The HTTP adapter shares session, origin, bounded JSON, private-cache and generic-error handling with compensation previews. Full verification, populated upgrade/restore, exact-head CI and authenticated staging remain required. Production migration and promotion remain owner-reserved actions.
