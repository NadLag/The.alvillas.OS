# ADR 0231 — Native onboarding Booking Channels

Use the existing Core BookingChannel and its canonical writer. The native step records LINK or CONFIGURE for the actual saved Property after Team; it introduces no parallel listing, integration account or agreement model. Approved organization policy must explicitly choose the supported modes and required channel count. A bounded request is a protocol limit, not a default business configuration.

Reuse Core input validation and its source-key normalization. Require explicit synchronization mode, import/export flags, status and optional fields. An explicit null endpoint retains the existing encrypted endpoint, matching the canonical writer. Configuration cannot claim that a provider connection is verified or that the Property has been activated.

Preserve the exact submitted command in a purpose-bound private envelope tied to organization, session, revision, Owner, Property, creator, nonce and policy version. Original configuration snapshots contain only the canonical masked endpoint and whether one was configured. Never export stored endpoint ciphertext or substitute current values for retained originals. Reuse the existing Core endpoint masker so storage summaries and history validation cannot disagree. New and updated sources must retain their actual identities and creation attribution.

Native source authorization, transactional canonical configuration, immutable admission, additive227 database guards, safe read projections and localized UI now register this producer in shared dispatch. Targeted native/routing/security acceptance is qualified; complete local/native/browser/restore and exact-head dependency CI remain release gates. Keep migration227 and every earlier applied migration immutable. Do not start provider work, change production or deployment configuration, rewrite financial history, or infer booking-source commissions from a source name.

The existing Core channel writer had five proven authorization defects (3505:1 pass/5 failures). Its corrected current/held Property checks bind actual geography and caller before the private write and after the audit; all6 unchanged native cases and15 existing Core units pass. The native metadata-first source adapter adds12 passing real PostgreSQL cases and2 credential-free read projections. Stored ciphertext is never selected, and original submitted endpoints remain only inside the purpose-bound encrypted command. Admission, selectors, shared routing and UI are now implemented; complete release acceptance remains required.

The shared review and read schemas return a credential-free draft. The original submitted endpoint remains only in the encrypted command and temporary client form state; confirmation sends that original draft after comparing its safe presentation with the reviewed response. Session storage retains only the nonce. Original history uses captured masked values and current metadata authorization, without loading replacement private channel values. Operational entry loads options without decrypting financial or Team predecessors.

A real independent canonical writer could change the channel between native source capture and commit (3534). Reuse the existing Property advisory lock before reading or writing canonical channel values, then repeat current authority after waiting. The unchanged regression3535 observes an actual PostgreSQL transaction lock wait, then verifies original capture. No new locking abstraction, provider action or business rule is introduced.

Shared source error aliases must not load the framework request service during native browser fixture discovery. Move the existing Core errors into the existing Core access module and re-export those same constructors from the service and native adapter. Preserve all original names, messages, instanceof identities and HTTP denial mappings. A regression blocks next/headers at import time;35 affected unit and6 actual canonical authority cases pass. The HTTP browser fixture uses the existing canonical manual form, without duplicating the writer or copying administrator cookies.

The canonical manual channel editor follows Property edit authorization, including actual geography, lifecycle and creation time. It previously inherited the financial ownership-edit gate despite using an operational writer. Preserve the ownership gate and verify that a real operator can configure channels while ownership edit controls remain unavailable. The original production browser failure and its trace are retained; current browser acceptance remains a release gate.
