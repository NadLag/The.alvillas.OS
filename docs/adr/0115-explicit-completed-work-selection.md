# ADR 0115: Choose actual completed-work contracts and recover uncertain saves

Status: Accepted for integration; full compensation and staging acceptance remain outstanding.

The run editor reads the explicitly configured earning calendar and supported currency catalog after checking current creation and view authority. Work selection uses genuine completed tasks and their canonical effective-dated role-assignment contracts. Archived completed work remains financial evidence. Every selectable rate requires independent salary access before private rate configuration is resolved. Existing assignment, completion, configuration and monetary validators decide eligibility. Overlapping contracts remain separate choices; the operator explicitly chooses one contract per job. The canonical creation command independently validates the complete selected artifact and beneficiary totals.

Completed-work pagination retains PostgreSQL's original microsecond timestamp and task identity. Encrypted cursors bind the organization, actor, earning dates and currency. The selector rechecks actual sources, configuration and grants before returning a private read receipt. Saved details and selectable work share one independent source-label authorization helper.

The browser retains selected identifiers and form input in memory. Persistent tab storage contains only an opaque idempotency nonce, namespaced by the actual authenticated organization and actor. An uncertain response freezes the exact creation intent for retry. Reload recovery locks the same nonce as creation, requires the original creator, and performs the canonical audited source-authorized read. An unmatched nonce is reused so a delayed original request cannot create a second run under a new key. No financial payload, cached grant, editable rate or financial-command queue is stored in the browser. Saving creates a reviewable expected-value draft; payable recognition, approval and payment remain separate boundaries.
