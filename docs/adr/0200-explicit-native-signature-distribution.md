# 0200 — Explicit native signature distribution

F-DOC-06. All 355 approved features remain required.

Distribution is a separate reviewed command after private provider preparation. Reuse the existing signature intent, attempt, encrypted evidence, authorization, configuration, audit and outbox infrastructure. Capture the original preparation evidence, actual archived PDF, native recipients, provider account and legal configuration. Require independent current and held signature edit, source, template, financial and counterparty authority. Browser storage contains only the scoped recovery nonce; private review data stays in memory and is cleared on authority loss.

Commit the unique SEND attempt and its audit before the single EMAIL distribution POST. Verify the actual account, unchanged recipient contract and exact original PDF immediately before that effect. Preserve an acknowledged receipt before subsequent reads. A failed response cannot establish that distribution did not occur and cannot authorize a second POST. Authenticate readback against the original binding; record SENT only after the original request is observed as distributed with an actual signer sent status. A lost acknowledgement may use verified readback evidence without fabricating a POST receipt. Neither completion-looking metadata nor SENT establishes a native SIGNED event.

Explicit reconciliation requires a previous attempt and cannot admit or issue an initial send. An independently authorized current operator may reconcile after the original sender is deactivated. Private responses are reauthorized after provider reads and audit; independently verified system facts remain append-only even when human access is later revoked. Existing encrypted evidence identities and historical keys are unchanged. Shared evidence and provider-boundary helpers serve preparation and distribution without introducing another financial or document ledger.

Forward migration197 adds a nullable native provider-evidence reference to signature events and extends existing immutable guards for the separate SEND phase. A native SENT event requires its exact verified evidence and canonical audit in the same transaction. Native SIGNED and other unsupported transitions remain rejected. Original signature instance/version links, earlier drafts, document effective ordering and financial rows are unchanged. The populated196-to197 acceptance preserves all182 original table bodies and tuple versions and all196 earlier migration records/checksums. Applied migration197 is frozen; production application requires owner authorization.

Persistent authenticated webhook states, retained historical discovery under changed configuration, viewed/declined/expiry handling, signed PDF/certificate return (F-DOC-07), approved legal/provider configuration and authenticated hosted acceptance remain required. This decision does not mark a feature DONE or assert external legal/provider acceptance.
