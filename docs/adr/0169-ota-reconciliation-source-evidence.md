# ADR0169 — Shared OTA source reconciliation

The existing OTA settlement importer already creates sealed expected and receipt journals and an open Variance for every nonzero difference. Reuse that workflow and its financial sources. The shared reconciliation arithmetic now also exposes an evidence plan without a tolerance classification. Providers that have an explicit configured tolerance retain the classified plan; the existing bank plan keeps its exact shape and property order. The OTA adapter introduces no tolerance, conversion, write-off or accounting policy.

For newly admitted settlements, build the shared plan from the actual expected clearing posting and actual receiving-account postings. Check their exact totals against the retained settlement. A zero receipt has no synthetic zero posting: its evidence identifies the original settlement and fingerprints the actual receipt journal. The audit retains signed actual-minus-expected variance, reason, action, source posting identities and historical state. Existing Variance amounts and journals retain their current meaning. Retired or reversed sources never rewrite this historical audit.

Serialize duplicate imports by organization and original source transaction through the existing financial lock helper, acquiring source locks in sorted order. A replay reads the original expected journal, receipt journal and variance identity rather than creating another financial effect. The receipt acknowledgement is recoverable even when the original actual amount was zero. Check held and current financial authority after the final audit and before returning a retained acknowledgement.

No financial table, balance, source row or previously applied SQL is rewritten. Native acceptance covers original-row preservation, exact/short/over/zero receipts, simultaneous retries, audit failure, forced tenant isolation and independent grant revocation. Existing reservation browser acceptance checks the shared evidence and preserves it through the original refund flow.
