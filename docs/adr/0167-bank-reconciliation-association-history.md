# ADR0167 — Bank reconciliation association history

Bank reconciliation associates independently authorized original bank facts with the actual bank legs of sealed financial journals. It uses the shared exact reconciliation measure and Money adapter. The adapter projects bank-leg amounts, journal references and retained reversal identities; opposing owner and staff postings stay behind their own source authority.

Record immutable MATCH entries with positive allocation magnitudes and the original signed source amounts. Derive prior allocations from entries that have no RELEASE. A release is a new attributed association event, preserving the original plan and source witnesses. It creates no journal, changes no balance and never rewrites a financial or bank-source row. A nonzero variance retains its reason and explicit action and remains open even within the configured tolerance.

PostgreSQL independently enforces tenant isolation, source identity, currency precision, allocation budgets, current explicit bank policy, exact command intent, retained comparison and atomic audit. Commands reuse the existing financial lock helper in this order: actor nonce, bank allocation account, actual bank identity, configuration version. Source insertion takes the same bank identity lock. Held and current authority are checked independently for bank evidence and financial journals, including after the final audit.

Bank corrections append source facts. Missing originals, competing correction branches and deletions cannot be selected as current monetary facts. Later bank corrections or journal reversals make an existing association require review. A replacement cannot receive an allocation while any association of its earlier source versions remains active, including partial associations. The application projection and an additional native constraint enforce this family boundary. Releasing the earlier association makes its derived allocation capacity available for an explicit new review, while preserving every historical event.

Private reads and command recovery reuse the existing session, origin, nonce and presentation boundaries. Only an actor-scoped random nonce survives browser reloads. Recovery checks the original committed result under current read authority; it does not require a former write grant to remain active. Source and journal pages are bounded and use batch repository queries. The common arithmetic remains independent of storage and supports exact operational quantities without representing them as currencies.
