# ADR 0122: Settle earned employee claims through retained financial movements

Status: Accepted for integration; complete F-FIN-24 and staging acceptance remain outstanding.

An approved, recognized beneficiary claim can be settled through an explicitly recorded payment or an explicit offset against that beneficiary's actual staff wallet. Both operations reuse the existing employee payable posting recipes, financial journal writer and accounting-period boundary. A payment records an actual disbursement; it does not send money through an external provider. Neither operation recognizes the original work expense again.

Outstanding earnings are the original employee-liability credits minus actual settlement debits, including opposite reversal movements. They are derived from immutable postings for the actual claim, beneficiary and currency. No editable balance or parallel settlement table is introduced. The journal and its attributed, canonical immutable audit receipt follow the existing supplier-payment pattern. Exact command retry and actor-bound recovery retain the original journal. Corrections append a fully attributed exact opposite; they never overwrite a payment, reason or source cost.

The canonical recognition inspector validates the complete original submission, contractual work and actual beneficiary before a settlement. A selected claim must belong to that submission. Current source, salary, financial, payment and funding permissions are checked independently, retaining the original caller's restrictions. Multi-property financial aggregates require organization authority. Wallet funding additionally requires the actual wallet permissions, and an offset must use the beneficiary's own linked wallet. Identity's wallet calculation and person lock serialize offsets across different earned claims, advances and offboarding. The derived available wallet amount limits an offset independently of the amount owed.

The SQL boundary retains complete original recognition, exact canonical command identity, positive single-currency money, exactly balanced liability/funding postings and a new attributed audit receipt in the same transaction. Shared original-source locks and a final derived-liability constraint reject concurrent overpayment or invented earnings. Offsets additionally retain the actual beneficiary and nonnegative derived wallet amount. Reversal checks bind the exact original journal and receipt. Existing employee recognition and legacy wallet admission remain protected.

An absolute paid instant is retained. If its accounting period is closed, an explicit authorized current-period adjustment records the actual closed period and decision, original paid instant and current open posting instant. The record never silently substitutes another date. A future paid instant is rejected. User-facing local-date conversion remains subject to the configured accounting calendar.

Settlement and offset audits derive compensation privacy from actual guarded journal postings and the original beneficiary claim. Original-source salary and financial checks remain required; actual funding-account and wallet checks additionally protect the original paid instant and posting instant. An audit payload cannot grant authority. Audit listing and export retain the existing final stored-authority check.

The first new migration is immutable after admission. A direct malformed-receipt test exposed SQL null semantics around the command kind; a second forward migration strengthens typed canonical intent and new-journal receipt admission. The initial failing test and database are preserved. No existing migration, business row or financial history is rewritten. The payment workspace, other earning modes, earning corrections and authenticated staging remain required feature work.
